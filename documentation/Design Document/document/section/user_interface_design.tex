\section{User Interface Design considerations}

The Triplo smartphone application adopts a modular and controller-driven user interface design, where each UI page is responsible only for presentation logic, while business logic and data access are delegated to controllers and services.









\subsubsection{Smartphone Application General UI Patterns}

Across the application, the following design patterns are consistently applied:

\begin{itemize}
    \item UI components do not directly access Firebase or platform APIs; all interactions are mediated by controllers and services.
 
    \item The use of \texttt{Provider} and \texttt{notifyListeners()} ensures that UI components automatically update when underlying data changes.
 
    \item \textbf{Lazy loading:} Data-intensive operations are deferred using \texttt{FutureBuilder} to reduce initial loading time and improve perceived performance.
 
    \item \textbf{Navigation:} The use of \texttt{Navigator.pushReplacement()} and a shared Drawer ensures consistent navigation behavior across the application.
\end{itemize}


\subsubsection{Smartwatch Application General UI Patterns}

Across the application, the following design patterns are consistently applied:

\begin{itemize}
    \item UI components do not access Firebase or platform APIs; interactions with backend resources, pairing logic, notifications, and external services are mediated by controllers and service components.
    \item The use of \texttt{Provider} and \texttt{notifyListeners()}, similarly to the Smartphone Application UI
    \item UI elements are structured to fit the limited screen size of the smartwatch, using simplified layouts, compact cards, icon-based actions. Content-heavy pages, such as trekking and weather views, distribute information across multiple vertically scrollable or swipeable sections, avoiding overcrowded single-screen layouts.
    \item \textbf{Lazy loading:} Potentially expensive operations, such as user retrieval, diary loading, image resolution, and weather acquisition, are deferred through asynchronous calls and widgets such as \texttt{FutureBuilder}, similarly to what has been done for the Smartphone Application UI
    \item \textbf{Navigation} Navigation in the smartwatch application is also based on explicit transitions through \texttt{Navigator.push()}.
\end{itemize}

\paragraph{Note on the NavigationPage name.}
The name \textit{NavigationPage} is used in both applications, but it refers to two different UI concepts. In the smartphone application, \textit{NavigationPage} denotes the page related to compass and altimeter functionalities. In the smartwatch application, \textit{NavigationPage} denotes the page containing the main navigation buttons, namely the buttons leading to the home area, the user area, and the language-related options.
